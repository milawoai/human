## 改动与行为

`scripts/dev-cleanup.cjs` 供所有启动前任务共享，使用进程启动目录、命令路径及父子关系识别本工作区服务。识别后先 SIGTERM，等待最多 3 秒；未退出则 SIGKILL，再等待最多 2 秒。端口占用只查询 TCP LISTEN，不匹配客户端连接。发现无法确认属于本服务的监听者时退出失败，不终止该进程。检查权限、工具缺失及清理失败会阻止自动继续启动，用户仍应避免在 VS Code 提示中选择忽略失败。

后端检查 12002、9229，并识别 Nest watch / yarn 启动链；Python 检查 12003，识别本服务目录中的 Uvicorn reload 启动链；Electron 检查 12001、5200、5858、9222，同时识别本工作区 Electron 可执行路径、electron-vite 及其子进程，即使它们不占用端口。不会按系统内所有 Electron 进程统一结束。

`.vscode/tasks.json` 使用一次性 process 任务，去除 isBackground 与强制 exit 0。`.vscode/launch.json` 保留三个服务各自的启动前清理，增加 turbo 全服务入口清理。复合启动先执行共同清理，随后才启动各调试配置，避免 renderer attach 先连接到旧 Electron；各子配置仍保留自己的防护任务。

只读预演：`node scripts/dev-cleanup.cjs all --dry-run`。它仍检查端口归属，遇到其他服务占用时会明确报错，但不会发送终止信号。

## 限制与使用

当前脚本面向 macOS/Linux，要求 PATH 中有 node、ps、lsof。Windows 会明确报告尚未支持；原 lsof shell 清理也不具备原生 Windows 支持。本轮未在 Linux/Windows 或 VS Code GUI 中实测，不把脚本测试通过等同于调试器完整启动验收。

只覆盖这些 VS Code 启动入口，直接在终端执行 yarn 不会自动触发清理。PID 启动时间用于退出检查，降低 PID 复用造成的误判；不以任意用户输入拼接 shell 命令。工作区中若有其他独立 watcher 同时重启服务，最终端口检查会报错，需先停止相应启动器。强制结束分支存在，但本轮真实集成用例只验证了正常退出分支。
