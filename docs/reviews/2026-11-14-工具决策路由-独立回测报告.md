## 二、发现与修订后的复测标准

### F1 · P2 · 失败调用被作为成功经验写入错题本（已复现）

位置：[tool-router.service.ts:338](../../apps/backend/src/brain/basal-ganglia/tool-router.service.ts#L338)、[tool-search.agent-tool.ts:95](../../apps/backend/src/brain/basal-ganglia/tool-search.agent-tool.ts#L95)。

`recordRunOutcome()` 扫描 assistant 的 `toolCall` 时立即把工具加入实际集合 A；后续 `toolResult.isError=true` 不会撤销。隐藏工具也在 `target.execute()` 成功之前加入 `invokedHiddenTools`。这与讨论稿“实际成功调用集合 A”的定义不一致，后续 Few-shot 会强化失败或被拒绝的选择。

最小复现数据：

```js
// prepared.decision.selectedToolIds = ['good.read']
newMessages = [
  { role: 'assistant', content: [
    { type: 'toolCall', id: 'bad1', name: 'bad.write' }
  ] },
  { role: 'toolResult', toolCallId: 'bad1', toolName: 'bad.write',
    isError: true, content: [{ type: 'text', text: 'permission denied' }] }
];
```

调用 `recordRunOutcome()`，实际得到：

```json
{"actualTools":["bad.write"],"falseNegatives":["bad.write"],"isFalseNegative":true}
```

修订后的复测标准：区分“尝试调用”和“成功调用”，按调用 ID 关联执行结果；失败、被阻止、未执行成功的代理调用不作为成功正例。覆盖直接调用失败、代理失败、成功、同工具先失败再成功，以及代理已入选工具的既有回归场景。

### F2 · P2 · Worker 启动阶段没有即时响应取消（已复现）

位置：[插件 index.js:112](</Users/zhou/Desktop/human-tools/router/qwen3-jev-mlx/index.js:112>)。

`request()` 先 `await ensureWorker()`，之后才注册 abort 监听。启动过程中取消只能等 ready 后检查 `signal.aborted`，不会即时停止 Worker。这违反插件规范“收到取消时终止当前 Worker”的约定。宿主 Promise 竞速先返回，不代表底层进程已停止。

复现方法：用一个先睡眠 0.4 秒再输出 `{"type":"ready"}` 的 Python 假 Worker；通过 `workerPath` 指向它；执行请求后 30ms 调用 `AbortController.abort()`。

实际结果：取消后 100ms 检查，`childAlive=true`、`pending=0`；请求约 444ms 后返回 `CANCELLED`，返回后 `child` 仍存在。测试结束显式调用 `destroy()` 清理该探针进程。

修订后的复测标准：启动前后均响应取消；在 ready 前取消也能及时结束启动等待并销毁自己的 Worker。覆盖多个请求共享启动、启动超时、取消后下一次调用可重新启动；不能误杀其他插件或新一代 Worker。

### F3 · P2 · 在线配置命令与实现不一致（已在线复现）

位置：[brain-agent.service.ts:405](../../apps/backend/src/brain/agent/brain-agent.service.ts#L405)；测试规范“步骤 4 / 在线热切换路由模式并恢复”。

| 请求 payload | 实际返回配置 |
|---|---|
| `{"mode":"active","topK":5,"routeTimeoutMs":3000}` | `shadow / topK=6 / timeout=4000`，但 `success=true` |
| `{"setMode":"active","topK":5,"routeTimeoutMs":3000}` | `active / topK=5 / timeout=4000` |

实现读取 `setMode` 而非测试规范中的 `mode`，未透传 `routeTimeoutMs`；topK/threshold 的更新还要求同时给出有效 `setMode`。实现稿使用 `setMode`，测试规范使用 `mode`，两份说明也互相冲突。

复现入口：

```bash
curl -sS --max-time 10 http://127.0.0.1:12002/neural/trigger \
  -H 'Content-Type: application/json' \
  -d '{"kind":"query","topic":"brain.agent.router.status","payload":{"mode":"active","topK":5,"routeTimeoutMs":3000}}'
```

修订后的复测标准：统一公开字段与文档；确认支持哪些独立配置更新，并对非法值做校验。请求后另发空 payload 查询，断言配置确实生效；最后恢复测试前配置，而非只检查 HTTP 成功。

### F4 · P2 · 真实 Agent 接入未传递会话上下文（静态确认）

位置：[brain-agent.service.ts:478](../../apps/backend/src/brain/agent/brain-agent.service.ts#L478)。

契约、路由服务和 Python 引擎支持 `contextSummary`，但实际 `buildToolsWithRouting()` 只传 `userText / allTools / mode / signal`，没有传递前文摘要。独立 decide 接口支持该字段不能证明真实会话链路已接通。该问题影响依赖前文的工具筛选；本轮未宣称已复现完整业务失败。

修订后的复测标准：明确首期上下文来源与长度边界，或正式修订设计范围；通过真实 Agent 接入捕获路由请求，验证第二轮“按刚才的方法再处理这个文件”等表达能携带必要前文。不得将上下文摘要与播报摘要混用。

### F5 · P2 · Gate 8 可跳过且关键断言不足（静态确认）

位置：[tool-router-smoke.ts:355](../../apps/backend/scripts/tool-router-smoke.ts#L355)、[tool-router-smoke.ts:423](../../apps/backend/scripts/tool-router-smoke.ts#L423)。

当真实插件配置不存在时，Gate 8 的 `if (fs.existsSync(...))` 整体跳过，但末尾仍打印 `ALL 8 GATES PASS`。另未断言热推理 `<500ms`，只验证第一次决策来源；第二次回退到内置路由仍可能因选中 bash 而通过。本轮真实插件在正常环境确实执行通过，但通过提示不能替代完整断言。

修订后的复测标准：明确必测失败和可选跳过的策略，分别输出 PASS / FAIL / SKIP；同时断言冷、热调用来源；加入规范声明的热推理性能断言，记录候选数量及样本。不能把本机未安装插件时的跳过算为真机通过。

补充覆盖偏差：插件 `scripts/verify-human.mjs` 直接加载源码 Provider、手动指定 Python 路径，不检查宿主软链或安装 manifest。该命令通过只能证明此直接调用路径，测试矩阵中的“安装结构自检”仍需额外证据。其多工具用例也只断言 success，没有断言 read 和 TTS 均被选中。

### O1 · 在线准确率偏差（已复现，根因未定）

使用测试规范原文的三候选请求，重启前后均稳定漏选 read：

```json

  "topic": "brain.agent.router.decide",

      {"toolId":"pi-coding-tools.read","description":"读取本地文件内容"},
```

真实模型返回：

| 工具 | probability | 入选 |

| pi-coding-tools.read | 0.1887 | 否 |

复测标准：至少将该三候选用例纳入准确率回归；测试候选增删、描述改写、多步组合、普通闲聊、上下文指代。事先定义可接受工具集合、Recall@K / Precision@K 和阈值策略，避免只验证“返回了数组”或“包含某个工具”。
